# 週會宣導：《工程師的價值》Podcast 對談播放器

把一份角色對話腳本，變成一個雙擊就能播放的網頁——不需要 Python、不需要伺服器、不需要安裝任何東西，帶去早會用筆電或投影機開瀏覽器就能播。

## 特色

- **多角色對談**：主持人／工程師／主管／客戶，各有自己的音調、語速（瀏覽器內建 TTS，不是商用 AI 語音，見下方「誠實說明」）
- **字幕跟著唸到的地方變色**（karaoke 效果）
- **極簡插畫**會隨劇情換表情、換場景
- **語速可調**（0.75×～1.5×），配音設定裡也能單獨微調每個角色的音調／語速／指定系統聲音
- 播完停在「今日金句＋主管互動問題」的收尾畫面，**金句會由主持人的聲音唸出來**（主管互動問題不會唸，留給主管現場當面問）
- 結尾畫面可以打字回應主管互動問題，按「送出回應」會存成一個小檔案到瀏覽器的下載資料夾——**不連網、不上傳到任何地方**，是純本機存檔（見下方「回應收集與文字雲」）
- 主管專用的「備課筆記」收合區塊（不會被唸出來，只有主管自己看）

## 誠實說明（先講清楚，別讓同仁誤會）

- 聲音是**瀏覽器內建語音**（Web Speech API），不是 ElevenLabs／Azure／OpenAI 那種商用 AI 語音。不同角色聽起來不同，是靠音調＋語速＋（如果裝置有多種中文語音）分配不同系統語音做出來的，不是真的生成新聲音。
- 插畫是簡單的向量圖形（SVG），不是真的畫作。
- 字幕同步的精準度依瀏覽器/作業系統而定，中文尤其會有落差，當作「大致跟得上」就好，不是精確逐字。
- 每台電腦、每個瀏覽器裝的中文語音都不一樣，播放前建議先展開「配音設定」試聽一下，選一個聽起來順的聲音。

## 怎麼用

### 播放現有的一集
直接雙擊 `網頁/` 資料夾裡的 `.html` 檔，用瀏覽器打開即可。

### 新增一週的腳本
1. 在 `腳本/` 底下新增一個 JSON（可以複製 `04-把經驗變成能力.json` 改）。格式：
   - `roles`：這一集出場的角色，含顏色、音調、語速、預設表情
   - `scenes`：一幕一幕的對話，每句是 `[角色, 台詞]` 或 `[角色, 台詞, {expr, effect, sfx}]`（表情/特效/音效字可省略）
   - `golden_quote` / `manager_question`：收尾金句與主管互動問題
   - `prep_notes`（可省略）：主管備課用的參考資料，不會被播出
   - `phase`：屬於 52 週課綱的哪個階段（1～4，見下方「52 週四階段」）
   - `takeaways`：結尾「這集你最有感的是哪一點」的選項，通常就是這集的三個重點（跟 `bullets` 同內容、不含 ①②③）
   - `keywords`：統計打字回應時要數的關鍵字，挑 4～5 個這集的核心詞
2. 執行：
   ```bash
   python3 產生網頁.py
   ```
   會把 `腳本/` 底下所有 JSON 都重新產生成 `網頁/` 底下對應的 `.html`。也可以只指定一個檔案：
   ```bash
   python3 產生網頁.py 腳本/05-新的一集.json
   ```

## 背後怎麼運作

播放引擎（TTS 播放、字幕同步、插畫、播放控制、配音設定面板）來自技能 `.claude/skills/ai-dialogue-podcast-builder/`，是一份可重複使用的範本，不是為這個工具寫死的。`產生網頁.py` 只做一件事：把腳本 JSON 的內容套進範本，其他一律不碰——這樣以後每週出新集數，只要加一個 JSON，不用重寫網頁或程式。

如果之後想要真正的多聲線 AI 配音（而不是瀏覽器內建語音），需要接商用 TTS API（例如 OpenAI、ElevenLabs），那會需要另外處理 API 金鑰與後端，目前這個版本刻意不做，先求「零安裝、雙擊即用」。

## 回應收集與分析

### 結尾回饋怎麼設計（2026-10 起）

原本只有一個打字欄，再用「連續兩個字」統計做文字雲。實測發現它很容易拆出「點很」「把該」
這種沒意義的字詞，看不出大家到底記住了什麼，所以改成兩層：

1. **點選「這集你最有感的是哪一點？」**：選項就是這集的三個重點（腳本的 `takeaways`），
   點一下就能送出，不用打字。雲端版會即時顯示各選項的人數長條圖，一眼看出哪個重點最有共鳴。
2. **想多說一點再打字（選填）**：雲端版顯示這集關鍵字（腳本的 `keywords`）被提到幾次，
   以及最新三則回應的原文。

全部只做計數，不做斷詞、不送去任何 AI 服務。之後如果想要「AI 自動摘要所有回應」，
需要把同仁的回答送到外部 AI，要先跟 IT／資安確認過才做。

**QR Code** 指向入口網站的短網址（例如 `…/weekly-briefing/?r=10`），入口網站會轉到那一集、
直接打開結尾回饋畫面（不唸金句、不自動播放），手機上就看得到選項＋大家的統計。
短網址全是英數字，QR 很稀疏，投影在螢幕上也好掃。

### 舊的資料庫要加一個欄位（只做一次）

雲端版要存「選了哪一點」，D1 資料表需要多一個 `choice` 欄位。在自己電腦的
`tools/週會宣導/cloudflare/` 資料夾裡依序執行：

```bash
npx wrangler d1 execute weekly-briefing-responses --remote --file=migrations/001_add_choice.sql
npx wrangler deploy
```

順序反了也不會壞：新版 Worker 發現沒有 `choice` 欄位時，有打字的回應照常存；
只點選、沒打字的回應會失敗，播放器自動退回本機下載，不會憑空消失。

### 兩種收集模式

播放器結尾畫面加了一個回應欄，讓看完的人針對主管互動問題打幾個字。這條路線討論了很多輪
（Google Forms、Claude Artifact 共用資料庫、Cloudflare Workers + D1、瀏覽器下載到 NAS、
QR Code + 本機伺服器……），目前**兩種模式都支援**，靠 `RESPONSE_API_BASE` 這個設定值切換：

#### 模式一：純本機（預設，`RESPONSE_API_BASE` 留空）

- **播放器端**：按「送出回應」，瀏覽器用 `<a download>` 把回應存成一個 JSON 小檔案，
  存放位置就是瀏覽器的「下載」資料夾——跟平常點連結存檔的機制完全一樣，沒有任何連線動作。
- **集中回應**：把瀏覽器的預設下載資料夾設定成一個共用網路磁碟機（例如公司 NAS 上的資料夾），
  不用寫任何程式碼，每個人送出的回應就會自動落在同一個資料夾（IT 可以用群組原則統一推送）。
  沒有共用磁碟機的話，也可以手動用隨身碟／信件夾帶集中收起來的下載檔案。
- **分析**：打開 `文字雲.html`（現在叫「回應分析」），在「① 選擇回應檔案（本機）」把彙整好的一批 JSON 選進去，
  會看到每集「最有感的一點」各選項人數、原始回應，文字雲留作輔助參考。

這個模式**完全不連網、不上傳到任何地方**，符合公司資安政策明確禁止 API 連結／上傳檔案的情況。

#### 模式二：Cloudflare Workers + D1（`RESPONSE_API_BASE` 填了網址）

程式碼都在 `cloudflare/` 資料夾（部署步驟見那裡的 README）。設定好之後：

- **播放器端**：送出回應會直接打 API 寫進雲端的 D1 資料庫，不同裝置、不同人送出的回應會
  彙整在同一個地方；連不上的話會自動退回模式一的本機下載，回應不會憑空消失。
- **分析**：在 `文字雲.html` 的「① 或者：從雲端載入」貼上 Worker 網址跟 SITE_KEY，直接抓雲端資料。

**這個模式需要連網、需要呼叫外部 API（Cloudflare 的伺服器）**——如果公司資安政策明確禁止
使用外部 API 服務，這個模式不符合規定，請先跟 IT／資安部門確認過可以用 Cloudflare 再啟用；
沒確認過的話，維持模式一（`RESPONSE_API_BASE` 留空）就好，那個模式沒有這層疑慮。

**誠實說明**：`文字雲.html` 裡的文字雲用的是「連續兩個字」的簡化統計法（不是真正的中文斷詞），因為
真正準確的斷詞通常需要連網查字典，這個工具刻意不連網，所以用這個陽春但零風險的做法代替。
人數越多、統計才會越有意義；只有幾則回應時，字詞大小差異可能不明顯。

## 寫台詞的語氣（2026-09 之後統一走這個方向）

早期幾集（第四、五篇）是教育訓練式的長句、正經鋪陳。後來測試給更年輕的受眾看，
發現這種節奏容易讓人分心，所以從第六篇開始改成短句、口語、開場先拋反差或自嘲，
理論佐證（航空/醫療/服務品質研究等）從「正式引用」壓縮成「一句話帶過的附註」，
不當主要說服力來源。**之後新增的集數都照這個語氣寫**，不要走回第四、五篇那種
長句／正式鋪陳的寫法。

### 52 週四階段（按主題分，不按週數硬切）

專案全名《工程師的價值：52 週晨會故事 × 動畫教育訓練教材》。每集腳本的 `phase` 標記它屬於哪個階段，
入口網站每張卡片會顯示階段標籤：

| 階段 | 主題 | 目前的集數 |
|---|---|---|
| ① 建立使命感 | 為什麼這份工作重要 | 第 1、7 篇 |
| ② 建立專業習慣 | SOP、紀錄、準時、誠實 | 第 3、5、6、8 篇 |
| ③ 建立高績效思維 | 經驗變能力、危機處理、拿捏分寸 | 第 2、4、9 篇 |
| ④ 建立品牌文化 | 團隊當責、互相提醒、一致標準 | 第 10～13 篇 |

第一、二、三篇原始素材是使用者自己帶來的舊簡報／HTML 草稿（各自不同視覺風格、部分是純敘述沒有真正的對話），
已依現行語氣重寫成本工具的對話 JSON 格式、套用現行的扁平漫畫主題，內容不是逐字照搬原始檔案。

## 插畫引擎：角色手臂動作

`ai-dialogue-podcast-builder` 技能的 `assets/template.html` 播放引擎裡，每個角色現在除了頭部表情，
還會依表情播出對應的手臂姿勢（`armsSVG()`）：自信比讚、不好意思摸頭、嚇到雙手捂臉、
生氣/嚴肅叉腰、靈光一閃舉手指天等。角色圖案本身也有一個持續的輕微上下浮動動畫（`charBob`），
讓靜態插畫看起來更有生命力。

因為手臂顏色跟身體同色，貼著身體輪廓的姿勢（例如叉腰）如果沒有外框線，會直接融進身體看不出來——
所以手臂統一先描一層深色外框再疊色（`limb()` 輔助函式），跟臉部五官的線稿風格一致，
不管姿勢貼不貼著身體都看得清楚。這是播放引擎共用的部分，所有集數重新產生網頁後都會套用到。

## 手機／電腦版面

- **播放控制列黏在畫面底部**：手機上不用捲過整個漫畫框才按得到播放／上一段／下一段。
- **大螢幕（≥1024px，含投影）**：版面放寬到約 980px，字幕、角色、結尾金句都放大，漫畫框高度跟著螢幕高度走，一個畫面就看得到漫畫＋控制列。
- **結尾畫面整個跟著內容長高**：金句、主管問題、回應欄、QR Code、大家的回應都完整顯示，不會在框裡面被切掉。
- **QR Code 可以直接點**：電腦上點 QR Code 會開新分頁到回饋表單；手機上（自己的螢幕掃不到自己）改顯示一顆「開啟回饋表單 ↗」按鈕。

### 從 LINE／FB／IG 打開時，自動改用手機預設瀏覽器
App 內建瀏覽器（LINE、Facebook、Instagram、Messenger、微信……）常常不支援語音朗讀，所以入口網站和每一集網頁一開頭都會檢查：

| 情況 | 做法 |
|---|---|
| **LINE**（iOS、Android） | 網址自動加上 `openExternalBrowser=1`，LINE 會直接改用預設瀏覽器（Safari／Chrome）打開，不用手動 |
| **其他 App，Android** | 頂端出現提示條，按「用瀏覽器開啟」→ 交給系統預設瀏覽器 |
| **其他 App，iPhone** | iOS 不允許網頁強制跳出，只能提示「點 ⋯ → 在 Safari 中開啟」，附「複製網址」按鈕 |
| 一般 Safari／Chrome、相機掃 QR | 什麼都不做 |

`?r=09`、`?respond=1` 這些參數會原封不動帶過去。提示條可以按「先在這裡看」關掉。這段只看瀏覽器 UA、不連網，本機離線版也一樣安全。
